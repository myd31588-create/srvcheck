# 知识点梳理 · 从 0 到 1 做一个能卖钱的运维工具

> 这个项目从构思到上线只花了一天，但踩的坑和做的决策值得沉淀。
> 分三部分：技术实现 / 部署与跨平台 / 产品与获客。

---

## 一、技术实现要点

### 1. 零依赖设计的价值
整个项目**没有引入任何第三方依赖**（连 JSON 输出都是手写的）。收益：
- jar 只有 69KB，传输和启动都快
- GraalVM Native Image 编译时不需要处理依赖冲突
- 安全工具"零依赖"本身就是卖点（供应链攻击面小）

### 2. Java 17 新特性的顺手用法
- `record` 定义不可变结果对象（CheckResult）：一行搞定构造器/equals/hashCode
- `switch` 表达式 + 箭头语法处理枚举（Severity 得分系数）
- 文本块（text block）写 HTML 模板和帮助信息，不用拼字符串

### 3. 探测层设计：只读 + 优雅降级
- 所有探测走三个入口：读 `/proc`、读配置文件、执行只读命令（`ss`/`df`/`openssl`）
- **基类统一兜底**：非 Linux 环境 → SKIP；任何异常 → SKIP + 原因。检查工具崩溃是最丢人的事故
- 权限不足（如读 `/etc/shadow` 需要 root）不算错误，标记"未检测"并在报告中说明
- `ss -tlnp` 解析端口监听地址时，区分 `127.0.0.1`（安全）和 `0.0.0.0/::`（公网暴露）

### 4. 评分算法：分类内权重归一化
```
分类得分 = Σ(检查项权重 × 等级系数) / Σ(检查项权重) × 分类满分
等级系数: PASS=1.0  WARN=0.5  CRIT=0  SKIP=不计入分母
```
关键决策：**SKIP 不计入分母**——没检测到的项目不该拉低分数，否则"不支持"会被当成"扣分"，报告就没法看了。

### 5. 报告即产品：单文件 HTML
- 内联 CSS + SVG 条形图，不引任何外部资源 → **微信直发、离线可看**
- 用原生 `<details>/<summary>` 做折叠面板，零 JS 实现交互
- 双受众分层：前 40% 内容给老板看（大白话+分数+钱），折叠的明细表给技术人看
- 每条高危项带 `hint` 字段："后果 + 修复费用区间"——**把技术风险翻译成钱是整个产品的灵魂**

### 6. 一个小坑：Windows 控制台乱码
Git Bash 下中文输出乱码，`System.out` 默认跟随系统编码。修复：
```java
System.setOut(new PrintStream(new FileOutputStream(FileDescriptor.out), true, StandardCharsets.UTF_8));
```

## 二、部署与跨平台：踩过的两个大坑

### 坑 1：jlink 运行时是分平台的 ⭐ 最有价值的教训
**现象**：在 Windows 上用 jlink 裁剪出"最小 JRE"打进部署包，传到 Linux 服务器上直接跑不起来。

**原理**：jlink 产物包含目标平台的可执行文件（`bin/java` 是 ELF 还是 exe）和动态库（`.so`/`.dll`），在哪个平台跑就必须用哪个平台的 jmods 构建。

**解法：跨平台 jlink**
```bash
# 用 Windows 的 jlink 二进制 + Linux JDK 的 jmods 模块，产出 Linux 运行时
$JAVA_HOME/bin/jlink \
  --module-path /path/to/linux-jdk/jmods \   # 关键：指向目标平台的 jmods
  --add-modules java.base,java.logging,java.management,jdk.crypto.ec,jdk.crypto.cryptoki \
  --strip-debug --no-man-pages --no-header-files --compress=2 \
  --output runtime
```
- 验证方法：`od -c runtime/bin/java | head -2` 看文件头是 `ELF`（Linux）还是 `MZ`（Windows）
- Linux JDK 的 jmods 从 Adoptium/TUNA 镜像下载一次即可，缓存本地复用
- 模块选择经验：纯 CLI 工具 `java.base` 就够，加 TLS 需要 `jdk.crypto.ec`/`jdk.crypto.cryptoki`

**为什么不用 GraalVM Native Image？** 它能做到真正的单二进制，但构建慢、需要额外环境，是 P2 优化项。jlink 运行时（~17MB tar 包）是零成本折中。

### 坑 2：Windows 打的 tar 没有执行权限位
**现象**：部署包在 Linux 解压后 `./runtime/bin/java` 报 `Permission denied`。

**原理**：Windows 文件系统没有"可执行权限"概念，打出的 tar 里文件全是 `rw-r--r--`，Linux 解压后自然拒绝执行。

**解法**：解压后补一句
```bash
chmod +x /tmp/srvcheck/runtime/bin/*
```
已固化进 `deploy.sh` 的远程脚本，任何"从 Windows 打包传 Linux"的场景都适用这条。

### 部署脚本的健壮性设计
- **参数传递不用字符串拼接**：远程命令通过 `ssh user@host "VAR='...' bash -s" <<'EOF'` 的环境变量 + heredoc 注入，配合 bash 数组展开参数——带空格/中文的联系方式不会被 shell 拆坏
- 每步显式 `set -e` + 失败即停，远程执行完清理临时文件（不留痕迹是安全工具的素养）
- 本机找不到 mvn/JDK 时按常见路径自动探测，降低"换台电脑就跑不了"的概率

## 三、产品与获客：把工具变成生意

### 1. 定位差异化：换个"读者"就是换个赛道
Lynis 等开源安全工具输出英文明细给运维看；本产品输出**给老板看的中文报告**（分数 + 风险等级 + 修复费用区间）。技术上没有任何黑科技，差异全在"输出的接收者"——这是独立开发者找定位的通用思路：**不卷能力，卷视角**。

### 2. 作品即获客工具
报告尾部是可配置的"服务入口"（`--contact`）。工具免费体检 → 报告自然引导到付费修复/托管。**作品集和销售漏斗是同一个东西。**

### 3. 报价锚定在损失而非成本
"Redis 暴露公网 → 可能被拖库 → 修复 ¥500-1500"。客户不懂 `bind 127.0.0.1`，但懂"数据被偷"。报价三原则：
- 先讲损失再报价
- 只降范围不降单价
- 永远给两个选项（一次性修 / 月度托管）

### 4. 闲鱼等平台的合规红线
- 虚拟服务选"无需物流"
- 禁词："黑客/渗透"（删帖）、"加微信"（封号）
- 承诺写"查不出问题全额退"（可兑现），不写"修不好全退"（纠纷必输）
- 取证类需求（"查是不是前员工搞的鬼"）不接——法律风险
